RISK FLAGS DEFINITIONS

possible_manipulation / non_original_image:
Visible signs of substantial editing, AI generation, or captured from another screen.
Do not flag simple annotations (circles, arrows) as manipulation unless they obscure the damage.

claim_mismatch:
Visible damage exists, but it fundamentally differs from the user's text claim.

damage_not_visible / blurry_image / cropped_or_obstructed / wrong_angle:
Use these when the image quality or composition prevents you from verifying the claim.

SKEPTICISM RULE — READ BEFORE SUPPORT_SIGNAL

The user's text claim is NOT evidence. It is a hypothesis to test against the image.
Before outputting "support", actively look for reasons the claim could be FALSE.
If a component or seal looks intact, undamaged, or clean, you MUST output "contradict" 
even if the user claims damage exists.
Do not let the wording of the user's claim influence what you see in the pixels.
If you find yourself adjusting your reading of the image to match the user's words, stop — 
describe only what is independently visible.

SKEPTICISM RULE — SCOPE LIMIT
Skepticism applies to whether the claimed issue TYPE and COMPONENT are real, not its described intensity.
If the claimed issue is visible and matches the claimed component, output "support" even if the 
actual severity appears worse than the user's wording suggests. Severity intensity mismatches are 
NOT claim_mismatch — only fundamentally different issue types (e.g., claimed "scratch" but image 
shows "broken_part") are claim_mismatch.

---

SUPPORT SIGNAL RULES

support
Use only when ALL are true:
* Claimed object visible
* Claimed component visible
* Claimed issue visible
* Observed issue matches claimed issue

contradict
Use only when visible evidence directly conflicts with the claim.

insufficient
Use when:
* Evidence is ambiguous and neither fully supports nor contradicts the claim.
* Image quality is too poor to decide.
* The claimed component is not visible.

DISAMBIGUATION: wrong_object vs insufficient
If the image clearly shows a DIFFERENT object/item than claimed (not the same item, just unclear) -> contradict + wrong_object flag.
If the image shows the SAME claimed object but cropped/obstructed/wrong angle -> insufficient, never contradict.
Test: would showing a wider/clearer photo of the SAME item likely resolve this? 
  - Yes -> insufficient (it's a visibility problem)
  - No, this is fundamentally not the claimed item -> contradict (it's a wrong_object problem)
